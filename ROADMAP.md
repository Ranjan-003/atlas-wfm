# Atlas WFM — 18-Month Build Roadmap

This roadmap converts the static prototype into a production multi-tenant Workforce Intelligence Platform. It's structured into four phases with explicit success criteria, team sizing, and go/no-go gates. Each phase ends with a customer-facing deliverable, not just internal milestones.

---

## Phase 1 — Foundations (Months 1-3)

**Goal:** Single-tenant pilot. Forecasting + Capacity working end-to-end with one paying customer's real data flowing in via CSV.

### Scope

| Workstream | Deliverable |
|---|---|
| Forecasting Service | `forecasting-svc` v1: MA, Holt-Winters, Naive Seasonal, Croston, weighted Ensemble, walk-forward validation, MAD anomaly detection. MLflow registry. |
| Capacity Service | `capacity-svc` v1: Erlang C, Erlang A, chat concurrency, productivity model, FTE with shrinkage/occupancy, 12-week hiring plan. |
| Data Platform | Snowflake account, dbt seed models, CSV ingestion pipeline. Volumes-interval and forecasts tables partitioned. |
| Web UI | Dashboard, Forecasting module, Capacity module, Data Studio (CSV upload). Hash router. Auth via shared link (no SSO yet). |
| Infrastructure | EKS cluster (single region), Terraform IaC, GitHub Actions CI/CD, Datadog observability. |

### Out of scope (deliberately)
- Real-time / intraday
- Scheduling solver
- Multi-tenancy (use database namespace, not row-level security yet)
- AI Copilot
- ACD integrations (CSV only)

### Success criteria (go/no-go for Phase 2)
- One pilot customer's 90 days of history imported and producing forecasts at < 10% MAPE on > 50% of queues.
- p95 forecast latency per queue under 2s.
- Capacity recommendations directionally accurate enough that WFM lead sets schedules from them in week 2 of pilot.

### Team
- 1 EM
- 2 backend (Python/FastAPI, Snowflake/dbt)
- 1 ML engineer (forecasting)
- 1 frontend
- 1 designer (part-time)
- 0.5 SRE

## Phase 2 — Scheduling & Intraday (Months 4-6)

**Goal:** Close the loop. Once you can predict demand and translate it to FTE need, you have to actually staff and run the day. This phase adds the operational backbone.

### Scope

| Workstream | Deliverable |
|---|---|
| Scheduling Service | `scheduling-svc` v1: shift catalog management, greedy interval fitter, weekly roster generator, US/UK/EU/IN/PH compliance engine, schedule publishing workflow. |
| Intraday Service | `intraday-svc` v1: variance computation, SL pacing, tiered intervention recommender, adherence tracking. Event ingest from Kafka. Sub-second loop. |
| Connectors | First ACD integration: **Genesys Cloud CX**. Streams `intraday_event.v1` into Kafka via webhook + polling fallback. |
| Agent self-service | Mobile-web agent app: view schedule, request swap, request VTO/OT, set availability. Read-only first. |
| Roles | Initial RBAC: WFM Analyst, RTA, Ops Manager, Agent. JWT-based auth. |

### Decision gates
- **Solver choice gate (M4 W2):** Greedy vs CP-SAT for v1 fitter. Recommend greedy for v1, CP-SAT for Phase 4. Capture solver-quality benchmark before deciding.
- **Real-time architecture gate (M4 W3):** Confirm Go for `intraday-svc` hot path (vs Python). Build a 50k events/sec load test before committing.

### Success criteria
- 2 pilots running schedules generated by Atlas in production for ≥ 2 consecutive weeks.
- Intraday SL pacing visible to RTA team and demonstrably leading to interventions (audit trail proves the connection).
- p95 schedule generation for 200-agent week under 60s.

### Team
- + 2 backend (one for scheduling, one for intraday/Go)
- + 1 ML engineer (for AHT modeling and intraday anomaly detection)
- + 0.5 mobile/front-end

## Phase 3 — Multi-Tenant + AI (Months 7-12)

**Goal:** Move from pilots to SaaS. Multi-tenant from the database up, SSO, AI Copilot, AI Deflection modeling, full scenario engine.

### Scope

| Workstream | Deliverable |
|---|---|
| Multi-tenancy | Row-level security in Snowflake, tenant-aware caching layer, per-tenant rate limits, tenant-scoped audit logs. |
| Authentication | Okta + Azure AD SSO via OIDC. SCIM provisioning. MFA enforced for admin roles. |
| AI Copilot | `copilot-svc`: intent classifier (BERT base), entity extractor (queues, percentages, channels, dates), engine-routed grounded responder. Conversation memory per tenant. Templated answers + optional LLM polish (LLM cannot inject numbers). |
| AI Deflection | `deflection-svc`: tier modeling, residual mix recalculation, propagation to Capacity. Per-channel deflection assumptions configurable per tenant. |
| Scenarios | Persisted scenario versioning, approval workflow, scenario comparison UI, what-if export to PDF. |
| Connectors expansion | NICE CXone, Amazon Connect, Salesforce Service Cloud, Workday (read), Zendesk. Build a Connector Framework so each is < 2 weeks of integration. |
| Analytics | Forecast accuracy SLA dashboards, attribution analysis (which lever moved which KPI), volatility scoring, anomaly notebook. |

### Critical decision gates
- **Copilot architecture gate (M7):** Decide between fully deterministic vs LLM-augmented response composition. Recommend grounded-deterministic-first with LLM ONLY allowed to rephrase, never to compute. Document the boundary in an Architecture Decision Record.
- **Multi-tenant compute isolation gate (M8):** Shared k8s namespace vs per-tenant for largest customers. Drive by load test — if largest tenant degrades top-5 tenants by > 10% p95, escalate to dedicated nodes.

### Success criteria
- 8-10 paying customers in production.
- Copilot answers > 70% of operator questions correctly per labeled eval set; 0 hallucinated numbers in the last 1,000 logged answers.
- Time-to-onboard a new customer (signed contract → first forecast produced) under 2 weeks.

### Team
- + 2 backend
- + 2 ML engineers
- + 1 SRE
- + 1 frontend
- + 1 designer
- + 1 PM

## Phase 4 — Optimization & Scale (Months 13-18)

**Goal:** Be the best in the category, not just shippable. Real solver-based scheduling, scale to 100+ tenants, embedded experiences.

### Scope

| Workstream | Deliverable |
|---|---|
| Optimization Layer | CP-SAT-based scheduler (replacing greedy v1) with multi-skill, multi-site, fairness, and preference objectives. Gurobi fallback for tenants > 5,000 agents. Solver pool autoscaling. |
| Monte Carlo Simulator | Scenario engine with stochastic volume + AHT + shrinkage, 1000-run distributions, percentile-based hiring recommendations (P90 staffing). |
| Mobile Agent App | Native iOS + Android (React Native or Flutter — decide M13 W1). Schedule view, swap marketplace, AI assistant for self-service questions. |
| Embedded experiences | Slack and Teams bot for intraday alerts and scheduled briefings. Email digest. Mobile push for high-priority interventions. |
| Advanced analytics | Cohort analysis, agent performance attribution, what-explains-the-anomaly notebook, exec-summary auto-generated narratives. |
| Scale & reliability | Multi-region deployment (US + EU + APAC), 99.9% uptime SLA, disaster recovery (RPO < 15 min, RTO < 2 hours), SOC 2 Type II audit complete. |
| Marketplace | Connector SDK published; partners can build connectors. Bring on 5 marketplace partners by M18. |

### Critical decision gates
- **Solver vendor gate (M13):** Final call on Gurobi license (expensive, ~$50k/year/seat) vs continuing to push CP-SAT. Benchmark on 5,000-agent schedule.
- **Mobile platform gate (M13):** Native (Swift + Kotlin) vs React Native vs Flutter. Tied to whether we have iOS/Android specialists or generalist mobile.
- **Region expansion gate (M15):** EU GDPR first, then APAC. Tied to customer demand and infrastructure cost.

### Success criteria
- 30+ paying tenants, 3+ named tier-1 customers (10,000+ agents).
- Solver produces schedules within 5% of optimal in benchmark studies.
- Mobile app DAU > 60% of active agent base.
- 99.9% uptime over last 90 days.

### Team
- + 3 backend
- + 2 ML
- + 2 mobile
- + 1 SRE
- + 1 security
- + 1 frontend
- + 1 designer
- + 1 PM

## Risk register

| Risk | Mitigation |
|---|---|
| Forecasting accuracy plateaus on noisy short-history queues | Phase 1 explicitly tests with a low-volume queue. Have Croston + Naive Seasonal fallback documented. |
| First ACD connector takes longer than 4 weeks | Build a Mock ACD with replayable event streams (Kafka topic of recorded events) so other services can develop in parallel. |
| Copilot hallucinates numbers despite grounding | Add a deterministic "number check" filter that rejects any number in the response that wasn't produced by an engine call within this turn. Block the response, fall back to apology + suggested module. |
| Solver-quality benchmark underwhelms vs incumbents (NICE, Verint) | Phase 4 gives us time. Don't claim "optimization" externally until benchmark proves it. |
| Multi-tenant data leakage | Row-level security in Snowflake; quarterly red-team review of tenant isolation; SOC 2 Type II in Phase 4. |
| Key person dependency on ML team | Document model selection logic; pair-program; rotate the forecast SLA on-call. |

---

## What this roadmap does NOT include

- A general-purpose chatbot. Copilot is task-specific by design.
- An IVR or speech-analytics product.
- A payroll calculator.
- Anything claiming "agentic" autonomy in production-critical decisions. Recommendations are surfaced for human approval, always.

These are deliberate boundaries. Each one was tempting to expand into; each is its own multi-year product if you take it seriously, and we'd rather be excellent at five things than mediocre at fifteen.
